## 변경 전후 — 제3장 윤회 사이클

기존 순환 화살표는 한 글자도 건드리지 않고, 명부 아래로 갈라지는 축만 얹었습니다.

**전**

```
           ▲                    ▼
           └─── [ 명부 (Closed) ] ◀───┘
```

**후**

```
           ▲                    ▼
           └─── [ 명부 (Closed) ] ◀───┘
                        │
                        │ (원할 때, 몇 번이든)
                        ▼
             [ 결계 각인 · vX.Y.Z ]
```

그림 아래 본문도 두 문장 붙였습니다.

> 명부에 인이 쌓이면, 술자는 그 무덤들에 하나의 이름을 새길 수 있습니다. 이것이 `issue-version` 의 결계 각인입니다.
> 각인은 순환에서 갈라져 나올 뿐 **순환을 끊지 않습니다.** 인은 각인 뒤에도 계속 맺히고 풀리며, 다음 각인은 지난 각인 이후에 잠든 인들만 헤아립니다.

## 변경 전후 — 제4장 8번 절

**전** — `[설화]` · `[술식]` 두 줄뿐이었고 코드블록이 0개였습니다.

**후** — 아래가 추가됐습니다.

````markdown
```bash
/issue-version patch     # v0.3.2 → v0.3.3   버그 수정·문서 정리
/issue-version minor     # v0.3.2 → v0.4.0   기능 추가
/issue-version major     # v0.3.2 → v1.0.0   호환성이 깨지는 변경
```

한 번 부르면 절반만 갑니다. **1단계는 `release/vX.Y.Z` 브랜치에 8개 파일을 올린 bump PR 을 만들고 거기서 멈춥니다.** 그 PR 을 사람이 검토해 merge 한 뒤 같은 명령을 다시 부르면, 2단계로 태그를 달고 릴리즈를 냅니다.

이름을 새기는 일을 술식 혼자 끝내지 않는 이유는 하나입니다. 각인은 되돌리기 가장 어려운 술법이고, 되돌릴 수 없는 것 앞에는 반드시 사람이 서야 하기 때문입니다.
````

예시의 세 결과값은 지어낸 것이 아니라 실제 `plan` 출력입니다. v0.3.2 시점에 `patch`/`minor`/`major` 가 각각 `v0.3.3`/`v0.4.0`/`v1.0.0` 을 냈고, 그중 `patch` 는 [v0.3.3 릴리즈](https://github.com/Mineru98/samsara/releases/tag/v0.3.3) 로 실제 발행됐습니다.
