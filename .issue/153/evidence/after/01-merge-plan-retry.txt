1:### 결과를 보여주고 승인받는다
2:
3:**해소한 diff 를 사용자에게 보여준 뒤에만 push 한다.** resolver 결과를 그대로 밀지 않는다.
4:
5:```bash
6:git -C <워크트리> diff --stat
7:git -C <워크트리> diff        # 파일이 적으면 전문, 많으면 파일별로 나눠서
8:```
9:
10:승인 전까지는 커밋만 하고 멈출 수 있다. 한쪽에만 있는 경로가 남아 있으면 결정을 적용하기 전이라 `--continue` 가 거부되므로, 그때는 승인과 결정 적용을 마친 뒤에 돌린다.
11:
12:```bash
13:node <skill>/scripts/issue-merge.mjs resolve --worktree <경로> --continue           # 커밋만
14:node <skill>/scripts/issue-merge.mjs resolve --worktree <경로> --continue --push    # 승인 후
15:```
16:
17:`--continue` 는 충돌 마커가 하나라도 남았거나, 한쪽에만 있는 경로(`deleted-by-*`, `added-by-*`, `both-deleted`)를 아직 `git add`/`git rm` 으로 정하지 않았으면 커밋하지 않고 거부한다. 남은 파일과 줄 번호를 돌려준다.
18:커밋에는 추적 중인 파일만 담는다(`git add -u`). resolver 가 고친 의미 충돌과 재생성한 생성물은 들어가고, 검사가 새로 만든 파일은 들어가지 않는다. 재생성으로 새로 생긴 파일이 있으면 승인 전에 직접 `git add` 한다.
19:
20:한쪽에만 있는 경로의 결정(남김/지움)은 diff 승인을 받을 때 함께 묻는다. 삭제 결정은 diff 에 보이지 않으므로 경로마다 따로 적어 보여준다.
21:받은 결정은 즉시 적용하지 않는다. 경로별 결정을 `plan.md` 의 충돌 현황에 적어 두고, 해소 diff 를 승인받은 뒤 `--continue` 바로 앞에서 `git add`(남김) 또는 `git rm`(지움)으로 적용한다.
22:`--abort` 는 index 에 반영된 결정까지 되돌리므로, 결정을 일찍 적용하면 다음 단계로 올라갈 때 지워진다. abort 뒤 `resolve` 로 다시 깔았으면 적어 둔 결정을 같은 시점에 다시 적용한다. 사용자에게 다시 묻지 않는다.
23:
24:### 다시 확인한다
25:
26:push 한 뒤 같은 `--onto` 로 `preflight` 를 다시 돌려 `clean: true` 를 확인한다.
27:
28:해소가 실패하면 resolver 를 다음 단계로 올려 5절을 다시 돈다. 아래 중 하나면 실패다.
29:
30:```text
31:- verdict 가 partial 이거나 escalate 인데, 남은 항목이 제품 판단이 아니다
32:- --continue 가 마커나 생성물이 남아서 커밋을 거부했다 (remaining 에 hunks 나 unreadable 이 있는 항목, 또는 한쪽 경로가 아닌 kind 가 있다)
33:- push 뒤 preflight 가 아직 clean: false 다
34:- 6절 비판 서브에이전트가 해소 결과를 block 했다 (한쪽 변경을 버림, 근거 없는 해소)
35:```
36:
37:`escalate` 의 `options` 가 저마다 한쪽 이슈의 완료 기준을 깨는 경우는 제품 판단이다. 더 강한 모델로도 풀리지 않으므로 사다리를 올리지 않고 위 질문으로 바로 묻는다.
38:
39:사람 결정을 기다리는 상태도 실패로 세지 않는다. `--continue` 의 `remaining` 이 전부 마커 없는 한쪽 경로(`deleted-by-*`, `added-by-*`, `both-deleted`)이고 결정이 아직 없으면, abort 하지 않고 사다리도 그대로 둔 채 `references/ask.md` 3절 형식으로 경로마다 남길지 지울지 묻는다. 이 시점은 diff 승인이 이미 끝났고 abort 도 예정돼 있지 않으므로, 답을 `plan.md` 에 적고 바로 적용한 뒤 `--continue` 를 다시 돌린다.
40:`remaining` 에 마커와 한쪽 경로가 섞여 있으면 마커 쪽만 실패로 세어 다음 단계로 올린다. 한쪽 경로는 마커가 풀린 뒤 위 순서대로 묻는다.
41:
42:다음 단계로 올리기 전에 `resolve --worktree <경로> --abort` 로 판을 되돌리고 `resolve` 로 다시 깐다. 이전 단계가 남긴 편집 위에서 이어 붙이지 않는다.
43:새 resolver 프롬프트에는 위 기본 항목에 더해 아래를 넣는다. 같은 실수를 반복하지 않게 하려는 것이다.
44:
45:```text
46:- 이전 단계 번호와 모델·effort
47:- 이전 resolver 의 JSON 출력 전체
48:- 이전 해소 diff (git -C <워크트리> diff 를 abort 전에 저장해 둔 것)
49:- 실패 사유 — 위 네 가지 중 무엇이었는지, --continue 의 remaining, preflight 의 conflicts, critic 의 blocking 항목
50:```
