## 작업 요약

`issue-end` 스킬의 "마무리 보고" 출력을 #34 에서 정한 것과 같은 규칙으로 마크다운 표(table)로 바꿨다. 항목 순서·이름은 그대로 두고 표현 형식만 변경했다.

## 변경 대상 및 내용

문서(마크다운)만 다뤄 화면 캡처 대신 실제 diff 를 증거로 남긴다.

### `skills/issue-end/SKILL.md` — 메인 "마무리 보고"

**Before**
```text
이슈      [#{issue_number} <제목>](<이슈 URL>)
브랜치    <이름>
워크트리   <context 의 worktrees[].display 값>
기본 브랜치 <base> (<판별 출처>)
증거      before <n>장 / after <n>장 (박스 <n>개)
미러      <mirrorRef> (fallback 이면 그 사실 명시)
코멘트    [리포트 보기](<이슈 코멘트 URL>) (신규 / 기존 갱신)
PR        [#<번호> <제목>](<PR URL>) 또는 "만들지 않음 — 사유"
상태      status:review (실패했으면 그 사실)
동기화    <메인 최신화 결과 또는 건너뛴 사유>
다음      <사용자가 고른 행동>

현재 단계 — issue-end 11단계(다음 행동 선택) 완료
```

**After**
```markdown
| 항목 | 내용 |
| --- | --- |
| **이슈** | [#{issue_number} \<제목\>](\<이슈 URL\>) |
| **브랜치** | \<이름\> |
| **워크트리** | \<context 의 worktrees[].display 값\> |
| **기본 브랜치** | \<base\> (\<판별 출처\>) |
| **증거** | before \<n\>장 / after \<n\>장 (박스 \<n\>개) |
| **미러** | \<mirrorRef\> (fallback 이면 그 사실 명시) |
| **코멘트** | [리포트 보기](\<이슈 코멘트 URL\>) (신규 / 기존 갱신) |
| **PR** | [#\<번호\> \<제목\>](\<PR URL\>) 또는 "만들지 않음 — 사유" |
| **상태** | `status:review` (실패했으면 그 사실) |
| **동기화** | \<메인 최신화 결과 또는 건너뛴 사유\> |
| **다음** | \<사용자가 고른 행동\> |

> 현재 단계 — issue-end 11단계(다음 행동 선택) 완료

값이 없는 항목은 행을 지우지 말고 `-` 로 채운다.
```

### `skills/issue-end/references/report-and-pr.md` — "동기화" 행 예시

**Before**
```text
동기화    기본 브랜치 최신화 완료 (3 커밋 받음)
동기화    이미 최신이었습니다
동기화    건너뜀 — 메인 폴더에 저장 안 된 변경이 있습니다. 나중에 `git pull --rebase origin main`
```

**After**
```markdown
| 항목 | 내용 |
| --- | --- |
| **동기화** | 정상 최신화 — 기본 브랜치 최신화 완료 (3 커밋 받음) |
| **동기화** | 이미 최신 — 이미 최신이었습니다 |
| **동기화** | 건너뜀 — 메인 폴더에 저장 안 된 변경이 있습니다. 나중에 `git pull --rebase origin main` |
```

## #34 에서 배운 두 함정을 피함

- 배타적 예시 3개를 `<br>` 로 한 셀에 합치지 않았다 — SKILL.md 의 `<br>` 은 "한 보고 안의 줄바꿈" 문법이라, 합치면 "세 문구를 동시에 출력하라"는 의미로 오독된다(#34 2차 block 사유).
- 두 파일 모두 `| 항목 | 내용 |` 로 스키마를 통일했다 — 파일마다 다른 열 스키마를 쓰면 "표 형식으로 통일" 판정이 모호해진다(#34 3차 revise 사유).

## 검증

```bash
grep -n "마무리 보고" -A 20 skills/issue-end/SKILL.md
grep -n "동기화" -A 6 skills/issue-end/references/report-and-pr.md
```

두 파일 모두 `| --- |` 헤더 구분행과 열 개수가 맞는 표로 렌더링됨을 확인했고, `skills/issue-start/SKILL.md` 의 표와 동일한 `| 항목 | 내용 |` 스키마임을 diff 로 대조했다.
