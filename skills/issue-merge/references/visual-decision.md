# 시각적 의사결정 — 시안 먼저, 링크 먼저, 질문은 그 다음

AskUserQuestion 으로 정할 내용이 **눈으로 봐야 고를 수 있는 것**이면, 말로 설명하지 않고 먼저 시안을 만들어 보여 준다.
이 문서는 스킬 목록에 올라오지 않는 내부 절차이며, 아래 해당 조건에 걸리는 순간 다른 판단보다 먼저 읽는다.

## 해당 조건

```text
해당함    레이아웃·배치·간격, 색·타이포·아이콘, 컴포넌트 모양(버튼·카드·모달·탭), 화면 전환·흐름,
          문구 위치, 빈 상태·오류 상태 표현, 반응형 동작처럼 "어떻게 보이는가" 가 선택지를 가르는 결정
해당 없음  라벨 이름, 브랜치·워크트리 배치, 커밋·push·PR 승인, 백엔드·성능·데이터 결정, 설정값 선택
```

선택지 둘 이상이 화면에서 서로 다르게 보이면 해당한다. 판단이 애매하면 해당하는 쪽으로 처리한다.

## 절차

```text
1. 시안 작성   선택지마다 화면을 만든다
2. 배포        prototype-serve.sh 로 띄우고 URL 을 얻는다
3. 링크 먼저   본문(평문)에 링크를 먼저 쓴다
4. 질문        그다음에 AskUserQuestion 을 호출한다
5. 정리        답을 받으면 서버를 내린다
```

순서를 바꾸지 않는다. 링크 없이 질문부터 하지 않는다.

### 1. 시안 작성

- 위치: `${TMPDIR:-/tmp}/samsara-prototype/<slug>/index.html`. 저장소 밖이라 커밋에 섞이지 않는다.
- 빌드 없는 정적 파일 하나로 만든다. 외부 라이브러리는 버전을 고정한 CDN 만 쓴다. 실제 API 는 호출하지 않는다.
- **선택지 하나가 화면 하나다.** 각 화면 제목을 AskUserQuestion 선택지 라벨과 같은 이름으로 붙인다. 같은 페이지에서 탭이나 나란히 보기로 비교되게 한다.
- 저장소에 실제 화면이 있으면 그 디자인 토큰·용어·컴포넌트 모양을 먼저 읽고 맞춘다. 비교 대상이 현재 화면이면 현재 모습도 함께 넣는다.
- 390px 폭과 데스크톱 폭에서 모두 깨지지 않게 한다.

### 2. 배포

```bash
bash <skill>/scripts/prototype-serve.sh "${TMPDIR:-/tmp}/samsara-prototype/<slug>"
```

- tailscale 이 로그인돼 있으면 tailnet HTTPS 로, 없으면 `http://localhost:<port>/` 로 띄운다. 출력의 `mode:` 가 어느 쪽인지 알려 준다.
- 스크립트가 URL 응답을 확인한 경우에만 성공으로 본다. 실패하면 출력된 에러를 그대로 보고하고, 링크를 지어내지 않는다.
- tailscale 이 설치돼 있어도 로그인 안 됐거나 serve 가 실패하면 localhost 로 다시 시도한다.

### 3. 링크 먼저 — 본문에 쓴다

AskUserQuestion 을 호출하기 **전에**, 같은 응답의 본문에 링크를 `[설명](URL)` 형식으로 쓴다.

```text
issue-start 7단계(구현)입니다. 탭 활성 표시를 어떻게 보여 줄지 시안을 만들었습니다.

[활성 탭 시안 비교 보기](https://host.ts.net:19400/)

- A 밑줄형: 활성 탭 아래에 굵은 선을 둡니다.
- B 채움형: 활성 탭 배경을 채웁니다.

위 링크에서 두 안을 비교한 뒤 아래에서 골라 주세요.
```

- `mode: localhost` 이면 "이 링크는 이 컴퓨터에서만 열립니다" 를 한 줄 덧붙인다. 원격 세션이면 사용자가 열 수 없으므로 5번 대체 수단으로 간다.
- 본문에는 선택지별 한 줄 요약도 함께 적어, 링크를 못 열어도 무엇을 고르는지 알 수 있게 한다.

### 4. 질문 — 링크를 넣지 않는다

**AskUserQuestion 의 `question`, `header`, 선택지 `label`·`description`·`preview` 어디에도 URL 을 넣지 않는다.** 이 영역의 링크는 클릭되지 않는 경우가 있다.
질문 제목은 "위 링크의 시안을 보고 골라 주세요" 처럼 본문을 가리키기만 한다.

```text
나쁜 예   question: "시안(https://host.ts.net:19400/)을 보고 골라 주세요"
좋은 예   본문: [활성 탭 시안 비교 보기](https://host.ts.net:19400/)
          question: "issue-start 7단계(구현)입니다. 위 링크의 시안 중 활성 탭을 어떻게 보여 줄까요?"
          options: "A 밑줄형 (권장)", "B 채움형"
```

선택지 라벨은 시안 화면 제목과 같은 이름을 쓴다. 현재 단계 표기와 질문 형식은 각 스킬의 기존 규칙을 따른다.

### 5. 정리와 대체 수단

- 답을 받으면 `bash <skill>/scripts/prototype-serve.sh stop <port>` 로 내린다. 같은 흐름에서 시각 결정이 또 남았으면 내리지 않고 시안을 고쳐 재사용한다.
- 시안을 만들거나 배포하지 못하면 본문에 그 사실과 이유를 한 줄 쓰고, 선택지 `preview` 에 ASCII 목업을 넣어 질문한다. 시안 없이 말로만 묻고 넘어가지 않는다.
- 사용자가 고른 안의 근거로 시안 링크를 이슈 코멘트·PR 에 남길 필요는 없다. 서버는 임시이므로 링크는 결정 뒤에 죽는다.
