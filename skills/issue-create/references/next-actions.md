# 다음 행동

이슈를 만들고 라벨 점검까지 끝났으면 사용자가 다음에 무엇을 할지 고르게 한다. 번호만 알려주고 끝내면 등록해 둔 이슈가 그대로 방치된다.

## 선택지 (순서 고정)

AskUserQuestion 으로 제시한다. 바로 착수하는 쪽이 기본값이다.

```text
질문   다음으로 무엇을 할까요?

1. 바로 착수 (권장)   $issue-start #<번호> — 분석하고 워크트리까지 만듭니다
2. 이슈 더 등록       $issue-create — 지금 떠오른 다른 건도 남겨 둡니다   ← 더 등록할 후보가 있을 때만 넣는다
3. 라벨 정리          라벨이 없는 기존 이슈에 라벨을 붙입니다
4. 여기서 종료        번호만 기억해 두고 나중에 시작합니다
```

2번은 고정 선택지가 아니다. **더 등록할 후보가 실제로 있을 때만** 넣는다. 판정은 아래 `더 등록할 후보란` 을 따른다.
후보가 없으면 2번을 빼고 남은 선택지를 위로 당겨 다시 번호를 매긴다.

## 더 등록할 후보란

이번 등록에 담지 않은, 사용자가 남기고 싶어 할 만한 별도 작업이다.

- 사용자가 이번 요청에서 함께 말했지만 분할·중복으로 이번에 등록하지 않은 건
- 분해·중복 검사 중 드러났으나 이번 범위에 넣지 않은 별도 작업

이런 후보가 하나도 없으면 "이슈 더 등록" 은 물어볼 것이 없는 질문이다. 등록할 내용이 없는데 매번 등록을 권하지 않는다.
후보가 있으면 무엇을 더 등록할지 한 줄로 함께 제시한다.

선택지를 제시하기 전에 재료를 모아 함께 보여준다.

```bash
gh issue list --state open --limit 10 --json number,title,url,labels
```

상황에 따라 권장 위치를 바꾼다.

- 6단계의 `UNLABELED` 가 0 이 아니고 아직 안 붙였으면 **3번(라벨 정리)을 권장으로 올린다.** 라벨이 없으면 `issue-start` 가 브랜치 prefix 를 추론하지 못한다.
- 사용자가 여러 건을 한꺼번에 말했고 그중 이번에 등록하지 않은 건이 남았으면 2번(이슈 더 등록)을 넣고 권장으로 올린다. 더 등록할 후보가 없으면 2번을 빼둔 상태 그대로 둔다.
- 그 외에는 1번이 권장이다.

이슈는 `[설명](링크)` 형식으로 보여준다. 세부는 SKILL.md 의 `링크와 경로 쓰는 법`.

## 1번 — 바로 착수

같은 번호로 `issue-start` 를 이어서 실행한다.

```text
$issue-start #<번호>
```

**초안 내용을 대화 컨텍스트에서 재사용하지 않는다.** `issue-start` 가 `gh` 로 실제 등록된 본문을 다시 받아와 그것을 기준으로 분석한다. 등록 과정에서 사용자가 웹에서 손봤을 수 있다.

`issue-start` 가 없으면 설치한다.

```bash
sh <migrate-skill-agent>/scripts/migrate-skill-agent.sh \
  --skill issue-start --target home --link --clone --flavor <claude|codex>
```

설치도 안 되면 **직접 구현을 시작하지 않는다.** 이슈 번호와 다음에 칠 명령만 안내하고 끝낸다.

## 2번 — 이슈 더 등록

같은 절차를 처음부터 다시 밟는다. 성숙도 게이트는 이미 통과했으므로 건너뛴다.

## 3번 — 라벨 정리

`references/label-audit.md` 를 따른다. 제안한 라벨을 한 번에 승인받아 붙인 뒤 이 4지선다로 돌아온다.

## 4번 — 종료

마무리 보고를 출력하고 끝낸다.

```text
다음      $issue-start #<번호> 로 언제든 시작하실 수 있습니다
```

## 하지 않는 것

- **코드 수정.** 이 스킬은 이슈 생성까지만 한다.
- **이슈 상태 변경·코멘트·PR.** 각각 `issue-start` / `issue-end` / `issue-merge` 의 몫이다.
- **사용자에게 묻지 않고 다음 스킬로 넘어가기.** 이 선택은 반드시 사용자가 한다.
